기록일: **2026-10-25 (KST)**. 상태: **오너가 정한 목표·범위의 기록 + 구현·실험 설계 제안**.
구현 완료, 지표 실측, 플랫폼 지원 또는 라이브 실행 승인을 뜻하지 않는다.

## 0. 소유 범위와 검토 결론

이 문서는 이번 오너 대화에서 정한 두 작업의 목표·우선순위·완료 조건을 소유한다.
기존 문서 하나에 합치면 고객 운영 계측과 새 상품 진단 실험의 책임이 섞이므로 별도 workstream으로 둔다.

- **단기:** 곧 진행할 기존 고객 운영 제품 데모에서 사용 지표를 확인하고, 박람회 현장에서 설명·체험·영업할 수 있게 준비한다. 행사일은 아직 미정이다.
- **중단기:** **2026-11-30까지** 상품 페이지 AI 판독 진단의 데모 페이지·제한된 실험·실측 결과를 마련한다. 정식 출시나 대규모 운영이 완료 조건은 아니다.
- **장기 1순위 유지:** 문의·리뷰 기반의 실제 문제 발견과 상품·설명·운영 개선. 새 진단은 운영 데이터가 없는 초기 판매자도 사용할 진입 기능이다.

검토 결론은 **위 범위에서 진행 가능**이다. 다만 재현한 읽기 경로와 실제 플랫폼 접근을 구분하고,
반복 관측 횟수를 일반화된 성공 확률로 바꾸지 않으며, 사용 지표를 위해 로컬 데이터를 중앙에 자동 전송하지 않아야 한다.
세 조건을 아래 목표와 완료 기준에 반영한다.

## 2. 단기 A — 사용 지표 대시보드

### 2.1 화면에서 답해야 할 질문

판매자가 실제로 사용하고 있는가, 준비된 대응을 채택·수정하는가, 어디에서 막히는가,
확인 가능한 결과까지 이어지는가를 보여준다. 기존 홈의 매출·주문 현황과 **제품 사용 지표**는 이름과 목적을 구분한다.

다음은 **최소 지표 구성 제안**이다. 기존 계측을 재사용하고 누락된 계측만 별도로 설계한다.
현재 구현·측정 가능 여부는 착수 시 저장소와 실행 결과로 재확인한다.

| 질문 | 지표·표현 제안 | 해석 경계 |
|---|---|---|
| 시작할 수 있는가 | 연결 시작 → 연결 성공 → 첫 수집 성공의 고유 판매자/채널 수 | 이벤트가 없으면 미계측. 기존 외부 analytics가 꺼진 것을 사용자 이탈로 해석하지 않음 |
| 실제로 다시 쓰는가 | 명시한 기간의 운영 행동 일수·활동 판매자 수 | 로그인·화면 열람과 운영 행동을 구분. 재방문·유지율은 필요한 기록과 관찰 기간이 있을 때만 표시 |
| 준비한 일이 쓰이는가 | 노출 → 열람 → 판매자 행동 → 확인된 완료의 건수 | 각 단계의 정의·분모와 확인 가능한 lane을 명시. 클릭·승인·발송·결과 확인을 합치지 않음 |
| 초안이 도움이 되는가 | 모델 초안이 준비된 업무 중 그대로 승인·수정 승인·동일 문장 재저장·대기·기타 상태의 건수 | 규칙·판매자 템플릿·유예 문구를 모델 초안으로 세지 않음. 대기는 거절이 아님 |
| 어디에서 지연되는가 | 노출→열람, 승인→실행, 실행→확인 등의 중앙값과 측정 건수 | 경과 시간은 사람의 작업 시간이나 절감 시간이 아님. 미확인·실패는 따로 표시 |
| 믿고 맡길 수 있는가 | 실패·미확인·재연결 필요 건수와 관측 가능한 데이터 범위 | 수집 실패·미연결·미관측을 0건으로 만들지 않음 |

표시 규칙:

- 기간·KST 기준, 대상 코호트, 집계 단위, 분자·분모, 마지막 집계 시점과 출처를 함께 보여준다.
- 실제 파일럿·내부 테스트·박람회 시연·합성 데이터를 구분한다. `REAL` 표시만으로 실제 판매자 사용을 판정하지 않는다.
- 원장의 업무 키로 중복을 제거한다. 재시도·재렌더·반복 시연으로 처리 건수나 판매자 수를 부풀리지 않는다.
- 분모 0은 비율 `N/A`, 계측 부재는 `미계측`이다. 성공 0건과 구별한다.
- 원장에 없는 방문일·이탈 원인·유지율은 추정해 채우지 않는다. 추가 계측 과제로 남긴다.
- 시간 절감은 같은 업무의 수동 기준선과 실제 사람 작업 시간을 측정한 뒤에만 주장한다.
- 리뷰·문의는 결과 확인 수준이 다르므로 검증할 수 없는 리뷰를 문의의 확인 완료율에 합치지 않는다.

### 2.2 배치와 완료 조건

**구현 제안:** 우선 판매자 PC에 있는 운영 원장에서 읽어 로컬 집계·표시한다.
공급자가 여러 판매자의 수치를 중앙에서 보는 화면은 별도의 전송 범위·동의·접근권한 결정이 필요한 후속 설계다.
이번 사용 지표 요구만으로 GTM/GA4·PostHog·Sentry를 켜거나 고객 원문·작업 큐를 공급자 서버로 복제하지 않는다.
기존 [Auth + Growth 계약](../standing/auth_growth_instrumentation_v1.md)은 참고하되 로컬 모드는 제품 범위 v1.14가 우선한다.

단기 완료 조건:

- [ ] 주요 지표마다 출처·집계식·대상·미계측 여부를 문서와 화면에서 확인할 수 있다.
- [ ] 실제 파일럿 집계와 시연 집계를 분리하고 원장 대조로 숫자를 확인한다.
- [ ] 동일 업무 재시도, 중복 노출, 분모 0, 미확인, 실패 사례에서 과장된 숫자가 생기지 않는다.
- [ ] 실제 사용 기록이 아직 없으면 그 사실을 표시한 채 시연할 수 있다.

## 3. 단기 B — 박람회에서 설명·체험·영업 가능한 데모

**목표 확정:** 기능이 한 번 작동하는 시연을 넘어 반복해서 보여주고 다음 상담·체험으로 연결할 수 있어야 한다.
아래 구성과 시연 길이는 구현 제안이며 행사 일정·부스 환경·가격은 미확정이다.

- **짧은 시연 동선:** 고객 운영 문제 → 근거와 대응 준비 → 판매자 수정·승인 → 결과·사용 지표. 3~5분 동선을 제안한다.
- **반복 시작:** 전용 시연 자료·상태로 복원하는 경로를 둔다. 실제 판매자 데이터나 운영 원장을 초기화하지 않는다.
- **연결 불량 대응:** 저장된 사례·실험 결과를 열어 설명할 수 있게 한다. 저장된 결과는 실행일과 함께 표시하며 방금 실행한 결과로 소개하지 않는다.
- **전시 자료:** 고객 개인정보·인증정보가 없는 허용된 사례를 사용한다. 실제 운영 화면을 보일 경우에도 공개 가능한 범위를 준비한다.
- **가능한 기능 설명:** 검증한 기능, 제한된 실험, 향후 계획을 구분한 지원표를 준비한다. 문의·리뷰 기반 개선은 장기 목표로 소개한다.
- **영업 동선:** 제품 설명 → 지원 범위·운영 방식 → 체험/상담 신청으로 이어지는 안내와 링크/QR을 제안한다. 가격이 미정이면 임의로 정하지 않는다.
- **상담 기록:** 필요한 경우 명시적으로 제공받은 최소 연락처·관심 기능·후속 연락 동의를 제품 사용 지표와 분리해 관리한다. 자동 연락·발송은 이 목표에 포함하지 않는다.
- **두 데모의 독립성:** 11월 말 신규 AI 판독 데모가 준비되기 전에도 기존 고객 운영 데모로 영업할 수 있게 한다.

단기 완료 조건:

- [ ] 발표자가 개발자 개입 없이 같은 흐름을 두 번 연속 시연하고 각각 초기 상태로 돌아갈 수 있다.
- [ ] 네트워크·모델 실패 시 저장된 사례로 이어가되 실패와 결과 출처를 숨기지 않는다.
- [ ] 상담 상대가 현재 제공 범위와 계획을 구분하고 체험·상담 신청 경로를 찾을 수 있다.
- [ ] 화면의 성과 수치에 실제 사용/시연/합성 표시와 기간·표본이 붙는다.

## 4. 중단기 — 상품 페이지 AI 판독 진단

### 4.1 오너가 확정한 제품 정의

> **AI가 내 상세페이지에서 무엇을 읽고, 놓치고, 지어내는가를 읽는 경로별로 진단하고, 무엇을 어떻게 고칠지 알려준다.**

리뷰너리 안의 진입 기능이다. 상품 출시 전 점검과 AEO·GEO 관점을 합치되 **찾힘·인용·노출 순위 개선은 측정하지 않는다**.
장기 문의·리뷰 개선과 별개의 초기 사용 이유를 제공한다.

| 사용 시점 | 입력·동작 | 결과 |
|---|---|---|
| 업로드 전 점검 | 버전 하나 | 읽힌 사실·누락·근거 없는 답변과 수정 권고 |
| 상세페이지 개선 | 기존 버전 A와 수정 버전 B | 같은 사실·질문·읽기 조건에서 판독 결과의 차이 |
| 제품 시안 비교 | 실물이 없는 시안을 페이지 형태로 구성해 비교 | 시안의 설명 전달·판독 차이. 실물 성능이나 구매 의향 검증은 아님 |

- **이미지 입력 필수:** 통이미지 상세페이지를 지원하고 판매자가 제공한 페이지를 제품의 렌더러에서 본다.
- **독자는 AI:** Claude·GPT·Gemini 등 실제 사용되는 모델을 API로 시험한다. 정확한 모델 ID와 실행 조건은 실험 기록에 남긴다.
- **진단·수정 권고만 제공:** 자동 수정·업로드·게시하지 않는다.
- **수정 주체 구분:** 항목마다 `셀러 수정 가능 / 플랫폼 제약으로 수정 불가`를 표시한다. 플랫폼 제약이 확인되지 않았으면 `확인 필요`로 남긴다.
- **타깃 순서:** 스마트스토어 → Cafe24 → 쿠팡. 이 순서는 샘플·재현 시나리오 확장 순서이며 실제 플랫폼 연동 지원 선언이 아니다.
- **횟수로 표현:** 같은 조건의 질문을 여러 번 실행하고 `15/16회`처럼 관측 횟수를 보여준다. 모델·실험일을 결과마다 표시한다.

### 4.2 읽는 경로와 1라운드에서 주장할 수 있는 범위

| 확정한 독자 경로 | 1라운드 재현안 | 판정의 한계 |
|---|---|---|
| 검색 인덱스형 | 제공된 HTML의 텍스트와 이미지 대체 정보 등 추출 가능한 입력을 만든다. robots 자료가 있으면 정책을 별도 점검 | 실제 검색 인덱스·모델 학습 데이터 접근이 아님. robots 미제공은 미확인이고 허용 표시도 실제 수집·색인·인용을 보증하지 않음 |
| 사용자 요청형 가져오기 | 통제된 로컬/데모 페이지에서 가져오기 경로가 반환하는 텍스트·이미지의 범위를 고정해 시험 | API에 입력을 구성해 준 재현과 특정 서비스의 실제 URL 가져오기를 구분. 서비스별 실제 접근 성공을 보증하지 않음 |
| 화면을 보는 에이전트 | 업로드 자료를 렌더링한 통제 페이지의 화면·스크롤 구간을 읽는 조건을 재현 | Aside/computer use 등 실제 도구를 썼는지, 화면 이미지 입력만 썼는지 표시. 실제 마켓 탐색 능력을 검증한 것으로 소개하지 않음 |

**실제 쇼핑몰을 에이전트로 돌아다니게 하지 않는다.** 경로 이름만 다른 동일 이미지 입력 세 개를
서로 다른 접근 실험으로 세지 않는다. 각 경로의 입력 표현·획득 방법·관측 가능한 범위를 남긴다.
해당 입력을 확보하지 못한 경로는 `미실험/자료 부족`으로 표시하고 실패나 셀러 책임으로 만들지 않는다.

### 4.3 정답·판독·누락을 분리하는 실험 제안

판매자가 확인한 사실표를 먼저 만든다. 사실표의 각 항목에 실제 페이지에 근거가 있는지도 표시한다.
시안은 판매자가 정한 **설계 의도/가정**을 정답 기준으로 삼고, 실물로 검증된 사실과 구분한다.

| 사실표와 페이지의 상태 | 기대 응답·판정 |
|---|---|
| 페이지에 근거가 있고 해당 경로에도 전달됨 | 정확히 읽었는지, 놓쳤는지, 다르게 답했는지 측정 |
| 페이지에는 있으나 해당 경로에 전달되지 않음 | 접근·추출·렌더링 문제로 구분. 모델 이해 오류로 단정하지 않음 |
| 판매자는 알지만 페이지에는 없음 | `알 수 없음`이 적절한 응답. 페이지의 정보 누락으로 권고하고, 맞혀도 판독 성공으로 세지 않음 |
| 페이지·자료가 서로 충돌하거나 정답이 불확실함 | 정답 보류·셀러 확인 필요. 임의의 답을 정답으로 만들지 않음 |

판독 모델에는 **페이지에 해당하는 입력과 질문만** 주고 채점용 사실표는 제공하지 않는다.
문자열·단위 비교로 판정 가능한 것은 명시적 규칙으로, 의미 판정이 필요한 것은 근거와 함께 검토한다.
모델의 자기 확신이나 같은 모델의 자기 채점만으로 정확도를 확정하지 않는다.

### 4.4 반복 측정·A/B 표시 제안

- 반복 횟수 `N`은 실행 전에 정하고 양쪽 버전에 동일 적용한다. **16회는 표시 예시이며 모든 실험의 고정 횟수로 확정한 것은 아니다.**
- 모델/버전·경로·페이지 버전·질문·프롬프트·추출/렌더 조건을 고정하고, 요청 간 대화 기억을 공유하지 않는다.
- 비교 버전의 제시 순서 편향을 줄이고, 한 조건의 반복 횟수를 사람 구매자 표본 수로 부르지 않는다.
- 각 질문에 `정확한 판독 / 누락·알 수 없음 / 오답 / 근거 없는 답변`의 횟수와 증거 위치를 보여준다. 판정 불가는 따로 표시한다.
- 실패·거부·중단을 숨기지 않는다. 예: `계획 16회, 유효 응답 14회, API 실패 2회, 정확 판독 13/14회`.
- `15/16회`는 **해당 조건에서 관측한 빈도**이며 독립성을 입증한 성공 확률·통계적 유의성·전환율이 아니다.
- A/B는 항목별 횟수·차이를 나란히 보여준다. 차이가 작거나 항목 간 결과가 엇갈리면 우열 판단을 보류하고 다음 수정 포인트를 제안한다.
- 모델 간 결과를 합쳐 단일 승률로 만들지 않는다. 모델·날짜·경로·버전·프롬프트/질문 버전·실행 조건·유효 응답 수를 함께 보존한다.
- 셀러가 수정한 버전을 같은 조건으로 재측정할 수 있게 한다. 재측정은 자동 페이지 수정·게시와 다르다.

실험 비용은 **버전 수 × 모델 수 × 경로 수 × 질문 수 × 반복 수**에 따라 늘어난다.
1라운드는 작은 고정 샘플과 사전 실행표·호출 상한으로 제한하고 전체 조합 실행을 기본값으로 두지 않는 것을 제안한다.
모델별 조건을 맞출 수 없거나 실행하지 못한 조합은 그 사실을 결과에 남긴다.

### 4.5 데모 페이지와 1라운드 완료 조건

페이지 흐름 제안: **자료·이미지 입력 → 사실표 확인 → 단일/비교 선택 → 실행 조건 확인 → 경로별 진단 → 수정 권고 → 재측정 비교**.
제품 시안은 같은 비교 흐름에서 페이지를 구성할 수 있어야 한다. 세부 URL·내비게이션은 후속 IA delta로 정한다.

- [ ] 버전 하나 진단, 기존/수정 버전 비교, 실물 없는 시안의 페이지 구성·비교를 데모에서 보여준다.
- [ ] 스마트스토어를 우선한 허용된 샘플로 이미지 입력·렌더링·질문·반복 측정·채점·결과 표시가 이어진다.
- [ ] 세 읽기 경로의 재현 범위와 미실험 경로가 드러난다. 확보하지 못한 실제 접근 결과를 만들어내지 않는다.
- [ ] Claude·GPT·Gemini 계열별 실행 결과 또는 미실험 사유가 구분된다. 실행된 조합만 모델 ID·실험일·관측 횟수로 표시한다.
- [ ] 누락·오답·근거 없는 답변의 사례와 수정 가능한 항목·플랫폼 제약·확인 필요를 구분한다.
- [ ] 원본/수정본의 결과와 재측정 이력을 열 수 있다. **개선이 없거나 더 나쁜 결과도 유효한 실험 결과**로 남긴다.
- [ ] 결과는 사전 입력한 예시 숫자가 아닌 실험 기록에서 나온다. 저장된 결과 재생은 당시 실행일과 함께 표시한다.
- [ ] 판매 설명에 아래의 측정 한계가 반영된다. 정확도·매출 증가의 임의 목표치를 완료 조건으로 만들지 않는다.

### 4.6 판매 설명과 제외 범위

설명 예시: **“이 페이지를 이 모델과 읽기 조건으로 반복해서 읽혔을 때, 어떤 정보를 읽고 놓쳤는지 보여드립니다.”**
비교 화면에서는 **“AI 판독 비교 A/B · 사람 구매 전환 테스트 아님”**을 명시한다.

제외: 검색 수집·노출 순위·인용 증가 측정, 매출 향상 주장, 페르소나 구매/장바구니/이탈 예측,
네이버 AI 브리핑 독자, 실제 쇼핑몰 에이전트 순회, 자동 상세페이지 수정·게시.
OCR 엔진은 실험 단계에서 미정이며, 로컬 LLM·GPU 도입은 이번 목표에 필요하지 않다.

참고 자산은 [fire-your-seo-agency](https://github.com/leopard627/fire-your-seo-agency)의
진단표·crawler-eye audit·재측정 루프다. 검색 노출·자동 최적화 범위는 가져오지 않는다.
[MIT 라이선스](https://github.com/leopard627/fire-your-seo-agency/blob/main/LICENSE)는 2026-10-25 확인했으며,
실제 코드·문서 일부를 가져올 때 대상 커밋과 저작권·라이선스 고지를 보존한다. 설치·실행은 이번 문서화에서 하지 않았다.

## 5. 기존 구조와 충돌시키지 않는 구현 경계

- 새 진단은 기존 리뷰 triage나 답변 초안과 다른 평가 작업이다. 기존 프롬프트·payload floor·판정 결과에 섞지 않는다.
- backend-only LLM egress, 판매자 PC 통신 허용 목록·최소 전송, 공급자 서버의 모델 호출 금지를 유지한다.
  이미지·HTML을 새로 모델에 보내는 계약은 해당 진단용 범위와 gate 검증을 설계한 뒤 추가한다.
- **“우리 쪽 렌더링”은 제품이 제공하는 렌더러를 뜻하며 중앙 서버 업로드·저장을 이미 채택했다는 뜻은 아니다.**
  데모의 로컬 렌더링을 우선 검토하고, 중앙 호스팅이 필요하면 처리 필드·보유·삭제·권한·동의를 별도 결정한다.
- 판매자가 제공하고 사용을 허용한 상품 자료로 시작한다. 임의 외부 URL 수집이나 인증된 마켓 접속으로 입력 누락을 보완하지 않는다.
- FE freeze에 대한 이번 delta는 **AI 진단 진입·결과 비교와 사용 지표·시연 경험이라는 목표**다.
  구체적 route·내비게이션·상태·디자인은 후속 설계에서 명시한다. 전면 리디자인을 승인한 것이 아니다.
- 플랫폼 지원 여부·마켓 실행은 [capability 표](../multi-channel-connector-roadmap.md)와
  [라이브 승인 계약](../standing/sellerops_live_approval_contract.md)을 계속 따른다.

## 6. 장기 목표와 아직 확정하지 않은 연결

**장기 1순위는 계속 문의·리뷰 기반 개선이다.** 진단 기능은 그 전에 들어가는 입구이며 기존 고객 운영 제품을 대체하지 않는다.

“이후 실제 문의로 AI 진단에서 발견한 정보 누락을 확인한다”는 연결은 **후속 가설**로 남긴다.
모든 문의가 빠진 정보 때문에 생긴다고 볼 수 없고, 문의가 없다고 설명이 충분하다는 뜻도 아니다.
이번 기록으로 문의·리뷰를 진단의 자동 정답 라벨로 쓰는 설계나 판매자 간 학습을 확정하지 않는다.
