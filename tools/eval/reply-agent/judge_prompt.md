# 별도 채점자 지시문 (결과를 묻는다 — 기준표 문구를 쓰지 않는다)

답글을 쓴 모델과 **다른 모델**이 이 지시문으로 채점한다(docs/standing/reply_agent_v1.md §4-1). 채점자는 어느 답글이 어느 방식인지
모른다. 기준표의 규칙 번호나 문구는 보여 주지 않는다 — 기준표를 맞췄는지가 아니라 결과가 좋은지를 묻는다.

사례마다 고객 리뷰 하나와 답글 A · B, 그리고 각 답글이 인용한 판매자 근거(`evidenceA` · `evidenceB` — 상품 정보 ·
운영 정책 · 과거 답변)를 읽고, 각 답글에 대해 아래를 답한다. 사실과 약속은 **그 답글의 근거와 대조**한다 — 자연스러운지가
아니라 맞는지를 본다. 같은 사례를 A/B 순서를 바꾼 입력(`judge-input-swapped.jsonl`)으로 한 번 더 채점한다. 두 번의 답이
다르면 그 사례는 위치에 끌린 것으로 보고 사람이 다시 본다.

`factsCheckableA` · `factsCheckableB`가 false인 답글은 근거 원문을 다 되살리지 못했거나 평가 중 지식이 바뀐 것이다 — 그 답글의
4 · 4-1은 「보류」로 답한다. 입력의 리뷰 · 답글 · 근거는 모델로 보내는 다른 모든 내용과 같은 절차로 개인정보가 가려져 있다
(`[전화번호]` 같은 표시).

1. 이 고객이 이 답글을 읽으면 자기 말이 제대로 읽혔다고 느끼는가? (예 / 부분 / 아니오) — 한 줄 이유
2. 이 리뷰를 다른 구매자가 읽을 때, 답글이 판매자를 더 믿게 하는가, 덜 믿게 하는가, 상관없는가?
3. 고객이 이미 해 봤다고 쓴 것을 다시 권하는가? (예 / 아니오 / 해당 없음)
4. 근거에 없는 약속(보상 · 날짜 · 조치 완료)을 하는가? (예 / 아니오)
4-1. 근거와 다른 사실 · 조건(숫자 · 단위 · 기한 · 대상)을 말하는가? (예 / 아니오 / 근거 없음) — 예라면 어느 문장인지
5. 리뷰에 질문이 있으면 답했는가? (예 / 아니오 / 질문 없음)
5-1. 리뷰가 말한 문제 · 질문이 여럿이면 빠뜨린 것이 있는가? (예 / 아니오 / 하나뿐) — 예라면 무엇을
6. 다른 리뷰에 그대로 붙여도 말이 되는 답글인가? (예 / 아니오)
7. 둘 중 판매자로서 그대로 등록하고 싶은 쪽: A / B / 둘 다 / 둘 다 아님

출력은 사례마다 JSON 한 줄: {"id":"C01","A":{"1":"예","2":"더","3":"아니오","4":"아니오","4-1":"아니오","5":"질문 없음","5-1":"하나뿐","6":"아니오","why":"…"},"B":{…},"pick":"A"}
