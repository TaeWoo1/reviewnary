# Reply agent evaluation (docs/standing/reply_agent_v1.md §4-1)

평가는 쓰는 쪽과 떼어 놓는다 — 같은 리뷰를 이전 방식(모델 한 번)과 답글 에이전트가 각각 쓰고, 사장님이 어느 쪽인지 모르는 채
매긴다. 고객 문장이 들어간 산출물은 저장소에 두지 않는다: 모든 출력은 `--out`(기본 `~/workspace/sellerops/holds/eval/`)으로 간다.

1. `run_eval.sh <cases.txt> <run dir>` — 평가용 백엔드(웹 데모 DB 복사본)에 대고, 사례마다 이전 방식 초안과 에이전트 초안을
   하나씩 만든다. `<run dir>/runs.jsonl`에 **이번 실행의** 이전 방식 초안 버전, 에이전트 실행 ID와 저장 버전, 초안이 없으면
   그 이유(사람에게 넘김 · 저장 안 함 · 생성 실패 · 생성 안 함)를 한 줄씩 적는다.
2. `build_sheet.py --runs <run dir>/runs.jsonl --out <dir>` — 복사본 DB에서 **그 버전만** 읽는다. 리뷰의 최신 초안을 가져오지
   않으므로, 이번 실행이 실패했는데 예전 성공 초안이 그 자리에 보이는 일이 없다. 버전마다 그 버전이 인용한 근거 원문을 같이
   읽는다.
   - `blind.html`: A/B를 무작위로 섞은 비교표(사장님 채점용). 답글마다 「이 답글이 본 근거」를 펼쳐 약속 · 사실을 대조한다.
     초안이 없는 쪽은 이유를 가린다(이유가 방식을 드러내므로) — 이유는 `key.json`에.
   - `key.json`: A/B가 어느 쪽인지, 각 버전 번호와 출처(model_version · author_kind · created_by), 초안 없음의 이유, 실행 기록
     (첫 검토 · 코드 검사가 건 규칙). 채점 뒤에만 연다.
   - `judge-input.jsonl` · `judge-input-swapped.jsonl`: 별도 채점자(다른 모델, `judge_prompt.md`)용 입력. 근거를 함께 싣고,
     A/B 순서를 바꿔 두 번 채점해 위치 편향을 본다. **리뷰 · 답글 · 근거는 백엔드가 모델에 보내기 전에 쓰는 바로 그 정제기**
     (`VocPreviewSanitizer#redactFullBody`, `Redact.java`로 호출)를 거친다 — 사장님 비교표는 원문, 외부 채점 모델은 정제본.
     정제 뒤에도 전화번호 · 이메일 꼴이 남으면, 또는 백엔드 클래스가 빌드되어 있지 않으면 채점 파일을 쓰지 않는다.
   - `facts.json`: 코드로 본 사실(연락처 · 링크, 리뷰 대가, 반품법, 길이, 미루는 문장, 범용 감사).
3. 사장님 채점 JSON + 채점자 결과(두 순서) + facts를 합쳐 규칙별 · 사례별로 비교한다. 채점자와 사장님이 어긋나는 사례가
   채점자를 믿을 수 있는지를 보여 준다.

사례 목록(`cases.txt`)은 `set|review_id|rating` 줄이다: `dev`는 규칙을 다듬을 때 본 사례, `held`는 처음 보는 사례.

**지식은 평가 중 고정한다.** 인용 근거 원문은 평가표를 만들 때 지식 테이블에서 다시 읽는다(지식을 고치면 조각이 새로 만들어져
예전 원문이 사라진다). 그래서 `run_eval.sh`가 시작 · 끝에 지식 지문(`knowledge-before.txt` · `knowledge-after.txt`)을 남기고,
`build_sheet.py`가 둘과 지금을 비교한다. 다르거나 원문을 되살리지 못한 답글은 사실 정확성 채점을 보류한다
(`key.json`의 `factsCheckable`). 평가하는 동안 복사본 DB의 지식을 고치지 않는다.

**이 평가가 재지 않는 것.** 모든 사례를 먼저 「대응 필요」로 정한 뒤 쓰므로, **어떤 리뷰에 답해야 하는지 고르는 판단은 이 표로
검증되지 않는다** — 답글 품질 비교용이다. 고르는 판단은 미리 쓰기가 실제로 고른 것과 사장님 판단을 따로 맞춰 본다. 리뷰 화면의 「초안 생성 · 다시 쓰기」 버튼은 에이전트가
켜진 조직에서는 에이전트를 돌린다(2026-10-28부터, `ReviewReplyService#generateByAgent` — 이전 방식으로 돌아가지 않는다).
이 표의 「이전 방식」 열은 그래서 에이전트를 끈 채 같은 버튼을 누른 결과가 아니라, 비교를 위해 따로 부른 이전 초안 경로다.
문의 품질은 이 표가 재지 않는다. 판매자가 실제로 얼마나 고쳐서
등록했는지(수정량)는 이 표가 아니라 파일럿의 초안 버전 이력으로 잰다.
